# OpenConsole docs — agent guide

Docusaurus 3 site for [vurulkan/kubernetes-openconsole](https://github.com/vurulkan/kubernetes-openconsole) (the
code repo; its `CLAUDE.md` maps the code). Served at `https://vurulkan.com/openconsole-docs/` from GitHub Pages.

## Map

| Path | What |
|---|---|
| `docusaurus.config.ts` | `SITE_URL` / `BASE_URL` (the address: change these two + `static/CNAME` to move), i18n (`en`, `tr` empty until M23), local search, Mermaid |
| `sidebars.ts` | the information architecture: Getting started, Installation, User guide, Administration, API & agents, Operations, Reference, Release notes |
| `docs/` | pages (`.md` = CommonMark, `.mdx` only when a page needs components) |
| `docs/release-notes.md` | generated by `scripts/release-notes.mjs` on `prebuild` / `prestart`; gitignored |
| `docs/reference/*.md` | **generated in the code repo** (`backend/cmd/docgen`) and copied here by `npm run reference:sync` from the commit in `reference.json`; never edit them here |
| `openapi/openapi.yaml` | the code repo's API description, copied the same way; `scripts/openapi-site.mjs` makes `openapi.site.yaml` (example server, permission notes; gitignored) |
| `docs/api/endpoints/` | endpoint reference, one page per operation, generated by `npm run api-docs` (docusaurus-plugin-openapi-docs) before typecheck / start / build; gitignored. `scripts/check-endpoints.mjs` fails when pages ≠ operations |
| `docs/api/` | API & agents: overview, quick start, agent recipes (`oc` helper, shell, Claude Code, Cursor), limits |
| `docs/operations/` | logging, Elastic (KQL and ES-QL examples), metrics + alerts, tracing, health probes, security model, hardening checklist, air-gapped, troubleshooting (403 reason table), FAQ |
| `src/pages/index.tsx` | home page; `static/img/screenshot-{light,dark}.png` from a k3d cluster with `hack/k3d/crashlab.yaml` |
| `screenshots/` | every docs screenshot: `scenes.mjs` (what to click), `record.mjs` (k3d → `fixtures/`), `shoot.mjs` (fixtures → `static/img/screens/*.webp`, en/tr × light/dark, deterministic); see its README |
| `src/components/Screenshot.tsx` | `<Screenshot id alt />` in `.mdx` pages: picks locale + theme, sizes from `static/img/screens/screens.json` |
| `src/css/custom.css` | colors = the app's brand indigo + slate dark surfaces; contrast overrides for the endpoint pages |
| `src/clientModules/apiListRoles.ts` | list roles the openapi theme leaves out (accessibility) |
| `.github/workflows/docs.yml` | PR: build (broken links / anchors fail), `reference:check`, preview artifact; `main` / manual: deploy to Pages |

## Rules

- `npm ci && npm run typecheck && npm run build && npm run reference:check` before every PR (same as CI).
- Reference lists (env vars, permissions, audit, metrics, ClusterRole, shortcuts) and the endpoint reference come
  from the code: fix them in the code repo, run its docgen, then bump `reference.json` here and `npm run
  reference:sync`. When a release ships, pin `reference.json` to its tag.
- Links between pages: absolute site paths (`/installation/connect-cluster#read-only-mode`); links into the code repo:
  `https://github.com/vurulkan/kubernetes-openconsole/blob/main/…`. Claims about code (security model,
  troubleshooting's 403 table) link to lines at the release tag (`blob/v2.22.0/…#L12`); re-check and re-pin them
  when a release ships.
- Operations examples (Elastic queries, scrape / OTLP settings, NetworkPolicy, registry copy) are run against real
  OpenConsole lines on k3d + docker; troubleshooting messages are copied from the code or produced on k3d.
- Open security findings stay in the private milestones repo: pages describe how things work and what the operator
  should do, never a list of known weaknesses.
- Commands in Getting started / Installation / API & agents are run on a throwaway k3d cluster before they go in
  (`kubectl --context k3d-oc-smoke`, never other contexts; API examples with a real API key). A step that wasn't run
  doesn't go in.
- Every command in a copyable block; every variable's default written next to it.
- Docs describe the latest release; pin examples to it (`2.22.0`, `?ref=v2.22.0`) and update them when a release ships.
- Light + dark theme; no emoji as icons. Lighthouse accessibility ≥ 95 in both (`?docusaurus-theme=dark`).
- A UI screenshot is a scene in `screenshots/scenes.mjs`, never a hand-made image; `npm run screenshots` must give the same
  bytes twice. User-guide pages start with the task ("**You want to:**") and end with a *Can't see it?* box naming the
  missing permission.

Plan: <https://github.com/vurulkan/milestones> → `kubernetes-openconsole/M17`–`M23` (docs series).
